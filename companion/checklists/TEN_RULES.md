# Ten Rules for Responsible Vibe Coding

Print this page or keep it beside your project. These are habits, not shortcuts around testing or expert review.

1. **Start with a person and a problem.** A prompt is not product discovery.
2. **Define “done” before building.** Write observable acceptance criteria and non-goals.
3. **Give the AI only useful, safe context.** Keep project notes current; remove secrets and unapproved personal data.
4. **Ask for a plan before consequential work.** Inspect first; split large changes into small slices.
5. **Limit the blast radius.** Use a practice environment, least privilege, checkpoints, and backups.
6. **Review the change, not just the explanation.** Inspect files, dependencies, commands, and diffs.
7. **Verify independently.** Run checks and test actual behavior; an AI claim is not evidence.
8. **Enforce access where trust exists.** A hidden button is not authorization; test data rules with separate users.
9. **Ship with a recovery path.** Know how to detect a failure, control cost, restore data, and roll back.
10. **Know when to stop.** Narrow scope or get qualified help for high-impact, regulated, safety-critical, or unexplained risk.

```text
IDEA → PLAN → BUILD → VERIFY → SHIP → IMPROVE
```
